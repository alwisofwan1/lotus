# CodeCanvas Module

## Purpose
CodeCanvas is the graph workspace for agent orchestration, terminal/browser nodes, notes, tasks, templates, graph runs, and canvas project persistence.

## Ownership
- `containers/` owns page composition and ReactFlow shell wiring.
- `components/` owns presentational canvas chrome, sidebars, controls, nodes, panels, and settings UI.
- `hooks/` owns reusable React state adapters close to existing UI surfaces.
- `services/` owns pure or framework-light canvas domain logic, persistence adapters, graph/run records, node factories, codecs, routing, and validation.
- `runtime/` owns page-level runtime command seams and lifecycle adapters that keep `CanvasPage` shallow.
- `ARCHITECTURE.md` records the scalable target folder structure, size budget, and refactor sequence.

## Local Contracts
- Canvas project boot/open/switch/close transitions must render a neutral restoring state while project metadata or snapshots are pending; do not present the "No project open" portal until restore finishes and there is truly no active project. Project switching should use the fast hydration path: restore the saved viewport instantly, suppress node/edge choreography while the incoming snapshot mounts, and avoid per-node backdrop blur during the switch. Focus and Fleet are project-scoped view state, not snapshot geometry: remember each project's focused/Fleet hero and Fleet rail scroll position across project/route returns, keep board and Fleet viewports separate, recompute the right rail from the current visible area, persist only canonical pre-focus node boxes, drop stale heroes safely, clear view state when a project closes, and let the latest overlapping select/open/active-close request win without changing the durable active project to a stale request. Failed opens must restore the prior durable project pointer, and incoming snapshots must load successfully before outgoing native Browser overlays are torn down.
- Canvas snapshots hydrate through `canvas-snapshot-codec.ts`; do not bypass schema validation/repair for persisted nodes or edges.
- Canvas Terminal nodes reuse the CodeSpace terminal runtime and must preserve `runtimeScope`, `runtimePaneId`, and `canvasTerminalId` injection contracts; failed/exited runtime panes must expose a visible recovery action instead of leaving blank or stale hosts. Typed or Auto-voice NL text sent to a single focused plain Terminal, plus explicit `tell/ask Terminal … to …` typed addressing, must preserve the user's literal payload, submit exactly once through canonical terminal encoding, await native confirmed-write truth, restore the draft on unavailable/failed delivery without overwriting newer text, and never emit a delivery cue for failed or unknown writes. Forced Dictate remains insert-only for review. Terminal identity is one persisted optional label shared by node header, overview glyph, Fleet, NL/voice targeting, and delivery feedback; `Terminal N` remains the stable default and addressing alias after rename, while runtime/session/node ids never change. Header rename opens on a name-targeted right-click, never double-click, because double-click remains available to the Canvas focus/unfocus interaction.
- Browser nodes follow the one-to-one Terminal-to-Browser constraint, must park native WebViews outside full-detail LOD, drag, or resize states, and must surface native IPC/runtime failures as recoverable UI instead of silent blank panes.
- Headless Agent nodes stay headless; interactive PTY behavior belongs to Live Agent nodes, Terminal nodes, or explicit promotion to terminal.
- Canvas live-agent MCP fleet projection must be graph-canonical first: every visible live Agent node in the active canvas project should remain discoverable in `lotus_list_fleet` even before its runtime registry entry publishes, with runtime status/session data overlaid when available. Agent-to-agent dispatch resolution must also accept visible graph agents by node id, project-scoped pane id, workspace id, or name so transient registry gaps do not make visible peers disappear. Canvas fleet provider metadata must reflect the agent runner (for example Codex agents report `provider=codex`) instead of hardcoding Claude.
- Live Agent PTY surfaces suppress passive xterm mouse-hover reports before PTY writes so TUI mouse tracking cannot flood Tauri `write_to_session`; keyboard input, paste, clicks, drags, and wheel reports still pass through. Live Agent xterm themes must keep the xterm background transparent over the existing calm Canvas PTY surface, and displayed output must pass through the live-agent ANSI normalizer so near-black Claude Code banner/background cells become transparent or softened ink tones instead of hard black rectangles; do not change the terminal backdrop/surface just to tune ANSI art. Live Agent readiness/activity parsing remains immediate, but visible xterm DOM writes must coalesce PTY bursts to at most one combined write per animation frame; pending renderer writes must be cancelled on unmount while the persistent PTY transcript remains the reattach source of truth.
- Live Agent runner badges resolve through the pure registry-aware runner visual identity seam: built-ins keep their branded marks, custom Claude-family runners keep their registry name with the Claude mark, the registered Pi runner uses the `π` glyph, and unknown custom runners use a terminal CLI icon. Identity shape stays stable while phase colour communicates status; non-logo marks must remain transparent and must never degrade into an unmasked solid square.
- Agent-done voice callouts must stay project-aware: live agents publish durable `{name, nodeId, projectId}` identity keyed by a project-scoped hook pane id (`canvas:<projectId>:<nodeId>`) and PTY session id for old reattached panes, project switches must not erase that identity, and finishes from a different project or from an unknown active-project context should speak the human project label when resolvable while same-project finishes can keep the shorter phrasing.
- Agent completion toasts use the persisted Canvas Notifications preference for auto-dismiss. Auto-dismiss remains on by default with adaptive same/background durations and hover/focus/background pause; when disabled, cards show no countdown and remain until opened or dismissed. Re-enabling auto-dismiss gives visible cards a fresh full countdown.
- Browser TTS speech promises must settle exactly once: explicit stop or replacement resolves the active utterance even when WebKit omits lifecycle callbacks, every settlement clears utterance/abort/watchdog handlers, and a bounded watchdog rejects speech that never receives a lifecycle callback.
- Turn-based cloud TTS must keep at most one native synthesis active and one latest replacement pending; replacement or external abort drops stale queued speech before synthesis, abort-safe playback must re-check ownership after asynchronous source preparation, and a bounded playback watchdog must release stuck output without wedging later speech.
- Voice-to-voice barge-in must be click-safe and stale-audio-safe: interrupt scheduled PCM playback through the tested audio stop envelope so future scheduled chunks cancel their gain ramps and go silent before source cleanup, route all output through a master gain that mutes while the user has the floor, use local mic PCM energy as an early barge-in guard while/recently after agent audio so output is cut before server VAD arrives, rely on server-VAD `interrupt_response=true` instead of sending an extra `response.cancel` for server `speech_started`, forward realtime `response_id` as `responseId`, drop audio deltas from cancelled response ids even after the user's utterance ends, quarantine no-response-id late deltas briefly after barge-in, and never play model audio while server VAD says the user is speaking.
- Voice capture has a single owner: classic push-to-talk STT and S2S live voice must never hold the mic at the same time. Starting push-to-talk while Live is active must end Live before opening STT; starting Live while push-to-talk is recording must cancel that recording without submitting a partial command before opening the duplex mic. Classic push-to-talk must show immediate post-stop transcription feedback, preserve OpenAI/Deepgram STT provider paths, honor the explicitly active STT provider without silently uploading Browser-selected audio to another enabled provider, snapshot bounded structured decoder context at capture start (separate ranked focused/personal/canvas keywords, explicit expected languages or one visible device-locale fallback, and command grammar only for explicit Command while Auto/Dictate stay neutral), hold confident transcript-language mismatches for review instead of sending them to the planner, apply bounded user-approved literal replacements once per configured pre/post-AI stage before routing/delivery, keep detailed classic-voice diagnostics local-only in a bounded in-memory ring while support projections exclude transcript/audio/context terms, expose pending mic startup as cancellable state, keep capture start cancel-safe, and bind stop/cancel to the provider that owns the turn, route Deepgram streaming STT only after its bounded ordered renderer upload queue flushes and a bounded post-finish final has a chance to correct the visible partial, reject incomplete turns on upload failure or queue overload instead of dropping speech, keep native audio buffering bounded on a separate lane from Finish/Cancel control, and use provider-driven final/closed events immediately with an adaptive fallback grace (short when text is already final, full when a hypothesis/no transcript remains), prefer direct HTTP NL models for voice command parsing while seamlessly falling back to headless/`claude --print` when no usable NL key/model is configured, and use deterministic/localized spoken confirmations for completed commands; do not block acknowledgement on model-composed confirmation text. Classic dictation polish is latency-sensitive: it must use direct HTTP only, never cold-spawn a CLI utility run, and must fail open to the corrected raw transcript when its bounded cleanup budget expires. Dictation polish must also pass the shared fidelity guard and fall back to the raw transcript if cleanup drops concrete details/negations or invents scope; short prompts below the fidelity evidence floor must skip model polish and remain deterministic after approved literal corrections. Explicit Command/Dictate hotkeys are one-turn capture overrides, and routing must use the target/context snapshotted at mic start rather than later Canvas selection. Their defaults remain `mod+shift+v` and `mod+shift+d`, but both must be remappable through the shared Canvas hotkey registry/store and Canvas Settings → Hotkeys, with conflict/reassignment/reset behavior inherited from that registry; recording must accept any trigger key with or without modifiers plus standalone `Cmd`/`Ctrl`/`Option`/`Shift`. Standalone modifier recordings must preserve the physical left/right side when `KeyboardEvent.code` or `location` exposes it, while generic persisted modifier bindings remain explicitly any-side for backward compatibility. The binding editor holds an exclusive recording lease so pressing an existing shortcut records it without also executing its command. A standalone modifier activates on release only when no other key participated, left/right mismatches fail closed, and a `Cmd` binding must not fire during `Cmd+C` or another ordinary chord. User-chosen voice bindings are global across Canvas and must be intercepted before focused editors or terminals consume them; when a plain typing key is assigned, Hotkeys settings must warn that its normal input is replaced while Canvas is open. Voice dispatch must not keep a parallel hardcoded V/D listener, and Voice settings must display the effective platform-formatted bindings rather than static labels. Untargeted repository-analysis requests must never reach or be answered by the Canvas utility planner: keep voice text for review and require a coding-agent target; explicit named-agent dispatch remains valid. The NL planner uses one strict discriminated `intents | answer | error` envelope, answers only grounded visible-Canvas questions in the user's language, and locally refuses repository inspection because it has no filesystem tools. Provider paths that expose spectrum samples must hold non-empty transcripts for review instead of auto-submitting when a sufficiently sampled capture contains no speech-like energy. Classic diagnostics should record the actual post-polish dictation text used for delivery plus an ordered mic-stop-relative milestone timeline through STT finalization, route resolution, optional polish, delivery request/acceptance or review hold, confirmed native PTY Enter write when available, first meaningful agent output, and turn completion. Auto-sent written dictation uses a local-only `turnId` and one unambiguous pending correlation per target agent: output before Enter acknowledgement, empty/control output, prompt echo (including partial echo), and standby-only chrome must not count; correlation expires after a bounded wait, and `latencyMs.agentFirstOutput` measures Enter-to-output independently from mic-stop total latency. Classic turns are owned from mic startup by one AbortController-backed coordinator: a newer turn, explicit cancel, Live Voice takeover, or unmount invalidates stale STT/polish/delivery completions before they can route text, mutate UI, or write diagnostics. STT finalization has an 8-second controller deadline that cancels the provider owner, polish stops waiting immediately on abort while retaining its 900 ms fail-open budget, and native delivery confirmation has a 5-second deadline that reports write status as unknown rather than claiming `written`. Browser, batch-cloud, streaming STT, and the STT hook must isolate generations/owners so a cancelled old stop/end cannot clear a newer capture on the same provider instance. Streaming STT caps renderer IPC work at 8 active/waiting chunks and native socket work at 32 chunks; overload is terminal for that turn because executing an incomplete transcript is unsafe. Support projections must omit `turnId`, prompt text, agent identity, and pane identity. Review-first Dictate is target-first: when the agent snapshotted at mic start exposes a live PTY `insert` capability, place the corrected transcript directly into that agent prompt without submitting it, keep the Canvas command field empty, and let the user review/edit/press Enter in the terminal. Explicit Dictate with a focused plain Terminal node must similarly resolve its `runtimePaneId` (falling back to node id), require a `live` or `detached` runtime, and write literal transcript text without Enter. These direct insertions must not wait for optional model polish. Only offline, headless, starting, or otherwise non-insertable targets may fall back to the existing editable command field. The fallback must not render a separate review strip, popconfirm, `Send now`, or `Discard` action surface; user edits or Enter cancel pending optional polish, Enter routes to the snapshotted target even if Canvas selection changes, Escape clears the draft, and new classic/Live capture stays blocked until the fallback draft is sent or cleared. Once fallback Enter begins delivery, Escape may stop waiting but must warn that native delivery may already have occurred rather than claiming the command was retracted. Auto-Dictate must use tracked delivery and may report `written` only after the ready agent's reply promise settles; the Live Agent PTY submit queue resolves that promise only after paste and Enter receive native write acknowledgements, rejects it on PTY write failure or disposal, and starting agents remain truthfully `queued`. Startup-buffered dispatches must remain separate FIFO turns, wait for each native-confirmed submit before starting the next, continue through already-accepted turns while reporting any per-turn write failures, cap at 50 pending turns, and reject the newest overflow instead of silently evicting an already-accepted turn. Disposed PTY submit queues are permanently closed and must reject later writes. A connected shell may buffer while its runner is still starting, but launch phase `failed` must reject new dispatches rather than creating a queue that can never flush. Support projections may expose only the fixed milestone names and durations and must remain transcript-free.
- The Push-to-Talk and Live Voice keys are app-level (Voice Core, Lotus #178): canvas claims them with `useVoiceHotkeyHandlers` in the turn controller and must not add its own ⌘⇧L or Push-to-Talk listener. They show in Canvas Settings → Hotkeys → "Voice (all modes)" but are stored in `lotus-voice-hotkeys-v1`, not `canvas-hotkeys-v1`. ⌘⇧V / ⌘⇧D, narration and auto-close stay canvas settings.
- Command-delivery visual feedback is node-generic and receipt-driven: typed/classic/Live/explicit NL agent dispatches and confirmed plain-Terminal submissions emit cues only for delivered or queued outcomes. Delivery events target Canvas node ids; exact input anchors are preferred with the receiving ReactFlow node shell as fallback. The Canvas animation timeline starts only after source/target geometry is placeable, reports completion to the queue, and relies on a bounded hard timeout only for missing targets.
- S2S native audio send must stay latency-bounded under renderer/WS congestion: mic audio uses a bounded native queue with lossy drop-on-overload counters, while close/interrupt/tool/session-update controls use a separate unbounded control lane so user control never waits behind audio chunks. Diagnostics may expose compact queue counters only, never audio/transcripts/session ids/secrets.
- Voice-to-voice lifecycle must be cancel-safe: stopping/unmounting while a realtime socket is still connecting must close any late-arriving session id instead of retaining a hidden zombie session, mic startup failures after connect must surface as an error and tear down the socket/playback, playback setup failures must not leave the start latch stuck, transport-side realtime closes while Live Voice is active must remain as visible retryable errors instead of silently returning to the command bar, speech-like local mic chunks must count as user activity and pause completed-turn auto-close while server VAD is still catching up, client-side auto-end must use the normal teardown path for explicit multilingual sleep/end phrases, completed-turn/tool-settle close, semantic listening-idle timeout, and max-duration guardrails, and stale async setup completions must never resurrect a closed live voice UI.
- Live Voice turn integrity is session-local and deterministic: execute each realtime `callId` at most once, reject tool calls that arrive while server VAD still gives the user the floor, and clear private correlation state on teardown/restart. A tool call that races final STT uses a short initial wait that extends only while partial user transcription is progressing, with a hard upper bound; final text resolves every pending waiter immediately. Parallel function outputs wait for the provider's response-complete boundary and produce one continuation response, with a bounded fallback for compatible providers that omit the boundary. Agent prompt delivery must remain truthful: ready targets progress from accepted to written or failed when `sendReply` settles, while startup-buffered targets remain queued and are never reported as written. Support diagnostics may record only sanitized turn ordinals, milestone names, and bounded durations, never call/session ids or transcript text. The live surface must replace generic Thinking copy with truthful phases such as finishing the turn, preparing a handoff, or preparing a response.
- Voice-to-voice Canvas control must route realtime function calls through the same safe NL intent registry and `CanvasCommandCenter`/agent-message seams as the typed command bar. Keep the realtime tool allowlist non-destructive by default except the explicit close/close-all voice tools, send sanitized function-call results back to the S2S provider without internal node ids/UIDs, and do not grant arbitrary shell/CLI execution directly to the realtime voice model; agent/CLI work must go through existing spawn/dispatch tools and live Agent nodes. S2S session instructions must explicitly tell the realtime model to use tools for canvas actions, wait for the tool result before claiming a Canvas action or prompt delivery succeeded, execute lightweight local tools such as dispatch immediately without delaying them for spoken narration, reserve one short preamble for operations expected to take noticeable time, execute explicit close requests (`close`, `close all <type>`, `close everything`) immediately without confirmation while still asking when the target is ambiguous, and follow an adaptive cockpit-copilot spoken policy: routine acknowledgements stay within one sentence and 14 words, clarifications ask one clear question, and evidence-bearing results follow the persisted `brief | normal | expressive` budget (up to 2/3/5 sentences) with key evidence and a next action when one exists; that shared verbosity preference must remain discoverable in both Canvas Settings → Voice → Speak and Voice → Live. Spoken length limits never constrain tool arguments or worker task payloads; replies mirror the user's language while preserving technical terms, names, paths, numbers, and versions, and never expose tool jargon/JSON/internal ids. Final S2S user transcripts (`speaker=user`, `isFinal=true`) are authoritative for structured `dispatch` compilation within one server-VAD user turn: a new user-speech start invalidates the prior transcript, while multiple tools in the same turn may reuse it. Constraint-bearing typed and Live dispatches share the deterministic `compileAgentDelegation` seam before delivery; deterministic compilation must not add a model round-trip, while vague/deictic typed and Live work share `refineDispatchText()` grounding. Live grounding must use the command bar's existing lazy model caller, fail open, and keep the original transcript verbatim while placing grounded text only in the packet Objective. Preserve the verbatim source transcript, add only scope-neutral evidence/done criteria, keep short clear tasks direct, and leave `say_to_agent` unwrapped. Live Voice ownership ends at faithful prompt delivery: resolve the concrete visible/custom agent, send the complete prepared prompt through `sendAgentMessage()`, and report only `delivered`, `queued`, unavailable, or ambiguous transport truth. Do not create orchestration runs, aggregate/verify worker results, persist voice tasks, wait for completion, or claim worker work is done. Those capabilities require separate product approval and a separate plan. Generic spoken “cloud agent” means Claude and must not route to CCS/CSP profile wrappers; CCS/CSP should be reached through explicit custom runner commands/profile presets, not advertised as generic live-voice spawn choices. Multi-agent live-voice spawn requests must preserve counts and runner groups through `spawn_agent.count` or grouped `spawn_agent.items` (e.g. two Claude plus three Codex) and return aggregate spoken feedback instead of acknowledging only the first runner. Voice context should show visible agent names as primary identity while internal resolvers handle runner aliases/ordinals such as Codex, Claude 1, Cloud two, canonical STS separators like `claude-3`, or custom runner labels. Greetings/social voice commands must use exact-message `say_to_agent` semantics instead of being rewritten into task-brief prompts. Active S2S voice sessions must refresh realtime instructions/tools when the Canvas live context changes so early turns do not rely on stale session-start roster state. Ambiguous voice targets must ask a short clarification question with visible candidate names instead of guessing, expose the small `choose_target` continuation tool so the user's short answer can execute the pending action, and sanitized function-call outputs may include clarification labels but never internal node ids. S2S voice should keep tiny app-side target memory so pronouns such as him/her/them/itu/dia resolve to the last successful visible target without relying on provider memory alone. Medium-confidence fuzzy agent targets must ask a confirmation question instead of auto-executing, while exact visible names and explicit ordinals may execute directly. Dev voice traces/diagnostics should carry sanitized context and live health snapshots (`socket`, `mic`, `playback`, `tools`, audio-delta count, issue summary) and expose a dev-only copy action for sanitized JSONL so stale-context, connected-but-silent, mic, playback, and tool-resolution failures can be diagnosed without exposing secrets or node ids. Realtime voice tool exposure should be context-aware: hide live-agent tools when no live agents exist, hide browser navigation when no browser node exists, expose `choose_target` only while a clarification is pending, and expire pending clarifications so stale short answers cannot execute old actions. Dev builds may show a compact voice tool trace overlay for realtime debugging, but the trace must remain sanitized: show heard target, resolved visible target, tool, preview, and success/error without exposing internal node ids/UIDs.
- CodeCanvas native file/image drops must resolve the concrete drop point before hover/selection state: try raw Tauri coordinates first, then DPR-scaled fallback for physical-pixel reports, and never route a pointed OS drop to a stale hovered node when point hit-testing misses.
- Canvas hotkeys must be command-aware, not just chord-aware: global/navigation modifier shortcuts may work across layers, but destructive node commands such as `close-node` must never intercept terminal/editor text-editing chords like Cmd/Ctrl+Backspace or Cmd/Ctrl+Delete while focus is inside xterm, inputs, textareas, or contenteditable controls.
- Collaboration ledger UI is opt-in launch context only: normal CodeCanvas routes stay clean, while explicit Swarm Task/Workflow routes may show the lightweight collaboration overlay for headless AgentNode coordination. Task-triggered overlays may fetch workspace-scoped Bridge/Swarm task data through shared Tauri APIs, focus matched AgentNodes, route back to Swarm through query-string return URLs, and spawn missing assignees through Canvas commands with an initial task brief plus durable assignee-to-node ledger mapping/lifecycle sync, project-backed run/task context, copyable projectId/runId MCP context, mailbox handoff/evidence/blocker messages, manual and MCP-mediated evidence/blocker recording (including direct project-backed MCP writes when projectId/runId are supplied and native task-store freshness when possible), live overlay refresh from native collaboration-record update events, idempotent Swarm feedback ingestion, mailbox-backed participant status/evidence projection, and lightweight ledger/mailbox/storage indicators, but CodeCanvas must not import Swarm modules directly.
- Shared `services/graph-run-record.ts` mirrors optional native engine `recovery` metadata for Factory crash holds. Rust-owned records must never be resumed by the TypeScript graph engine; Factory owns recovery presentation and authorization. No graph snapshot migration is required for this optional checkpoint field.
- Persisted node records must not include runtime-only callbacks; runtime command wiring belongs in adapters.
- Node views should use `CanvasNodeCommand`/`DispatchCanvasNodeCommand`; AgentNode, BrowserNode, CanvasSkillNode, CanvasSkillsNode, ContextNode, CriticNode, HumanGateNode, NoteNode, PlanNode, TaskNode, TeamNode, and TerminalNode are the initial command-seam implementations.
- Whiteboard shape stroke tiers live in `services/shape-defaults.ts`; renderer, Inspector, rough.js mapping, and snapshot repair must share those values. Shape SVG strokes should remain zoom-stable and not be visually replaced by ReactFlow resize chrome.
- Music node chrome must stay node-size responsive through `music-node` container queries and mirror Terminal/Agent header scale without the colored top strip. Landscape nodes use a split layout with a precise square/rectangular media pane, details, hover-stable super-compact playlist, and transport controls; narrow or short nodes degrade to compact/mini layouts without relying on viewport media queries. Long mix durations use clock-style `H:MM:SS`; its bounded gel/blur background must stay subtle and include a reduced-transparency fallback. Music playback must attach the YouTube bridge only after the concrete iframe URL exists, especially for async Tauri production wrapper URLs; do not set `playing` optimistically before player state confirms playback. YouTube embed restrictions must degrade to a visible Open-on-YouTube fallback instead of leaving transport stuck at `0:00 / 0:00`; do not bypass platform/video-owner embed restrictions.
- Canvas-level UI actions should route through `services/commands/canvas-command.ts` and `runtime/useCanvasCommandCenter.ts` before falling back to page-local callbacks; ⌘K sheet rows must use that seam for canvas mutations. Manual node-view close/open actions, NL commands, sidebars, and the ⌘K sheet must share this seam so enter/leave motion, removal delays, and auto-tidy stay consistent.
- Default node footprint tokens live in `services/canvas-node-placement.ts`, with live/headless Agent defaults in `services/canvas-agent-node.ts` and center-spawn sizing in `services/canvas-spawn-position.ts`; keep defaults large enough for terminal/agent readability and update factory/placement tests when changing them.
- Multi-agent command spawns without explicit coordinates should originate from the viewport center through `runtime/useCanvasCommandCenter.ts`, using a small burst cascade plus CSS enter stagger so NL/sidebar/palette agent creation feels intentional instead of blinking.
- Arrange Canvas must feel like one coordinated board move: `services/canvas-arrange.ts` keeps fit-mode cells capped/readable and centers short rows, `useCanvasNodes.arrangeNodes()` commits final positions in one state update, and `CanvasPage` enables ReactFlow wrapper `transform` transitions plus camera glide at the same time. Ordinary programmatic node moves use ReactFlow wrapper transform transitions while pointer drags are excluded. Zoom controls, focus, fit, restore, and arrange should use the shared premium viewport easing from `services/canvas-motion.ts`; deliberate camera moves must route through `runCanvasViewportMotion()` in `services/viewport/canvas-viewport-motion.ts` so semantic LOD stays frozen during the tween and button zooms preserve the viewport center. Node open/close uses CSS scale/opacity keyframes in `node-shell.css`; close motion must stay lightweight by avoiding animated border-radius, filter, or per-frame layout work. Do not reintroduce delayed camera catch-up, per-frame React state position tweens, mid-zoom LOD remounts, unanchored zoom jumps, or fullscreen sparse-node resizing, which makes nodes appear to blink, collide, or slide in from the right.
- `canvas-flow-config.ts` should inject the command seam plus small derived read models only; do not reintroduce broad per-node callback injection.
- Adopting a cell from a machine's Standalone Host branches on `RemoteHostCell.tui`, never on anything else, and `adoptionShapeFor()` is the only place that reads it: a `tui` cell becomes a Terminal node attached to its tmux session over ssh, a headless one becomes a `host-cell` node showing its conversation. Absent means terminal — a host older than the field only ever ran cells through its PTY manager. Both node shapes carry the pane id as `adoptedPaneId`, which is what stops ⌘K offering one cell twice, and all three persistence hops (`canvas-serialize`, `canvas-snapshot-codec`, `recordToNode`) must carry it or a reload turns an adopted node back into an ordinary one.
- The `host-cell` renderer treats `part.type` as open: the kinds it draws are a convenience, the fallback is the contract. An unrecognised part is rendered under its raw name (`rawType` first, for the host'"'"'s own `unknown` part) and never dropped — `services/host-conversation.ts` and its tests hold this. Refresh is polling by decision (`conversationPollDelayMs`): no stream exists on the `/v1` surface, one poll is one ssh round trip, so a node that is not at full LOD asks nothing and a settled conversation slows down rather than stopping.

## Work Guidance
- Prefer small runtime seams over adding orchestration directly to `CanvasPage`.
- Keep CodeCanvas implementation files around 300-400 LOC when practical and cap normal files around 500-600 LOC; split by responsibility before exceeding that range.
- Keep pure graph, snapshot, placement, codec, viewport, and run policies in `services/` with focused tests.
- Viewport/LOD/grid/native overlay/native BrowserNode bounds-sync behavior is owned by `services/viewport/canvas-viewport-policy.ts`; zoom/camera anchoring math belongs in `services/viewport/canvas-viewport-motion.ts`. Do not scatter new viewport performance thresholds or camera math across components or hooks.
- Native BrowserNode DOM observer and rAF/throttle scheduling mechanics belong in `hooks/useCanvasBrowserBoundsSync.ts`; keep `useCanvasBrowserNode.ts` focused on composing browser state with runtime adapters.
- Browser lifecycle IPC belongs in `runtime/adapters/canvas-browser-lifecycle-adapter.ts`; do not call canvas-browser Tauri IPC directly from BrowserNode UI or broad page containers.
- Browser auto-open-on-loading behavior belongs in `hooks/useCanvasBrowserAutoOpen.ts`; keep it out of the lifecycle IPC adapter and node view.
- Keep React-heavy rendering in `components/`; avoid mixing persistence or Tauri listener lifecycle into node views.
- S2S live voice orchestration for the NL command bar belongs in `services/voice/use-canvas-live-voice-controller.ts`: realtime instructions/tools, live context, target clarification, tool execution, trace recording, and diagnostics copy. Keep `CanvasNlCommandBar` as the composition/view shell for invoking that controller rather than reintroducing S2S tool orchestration inline.
- Realtime tool execution mechanics belong in `services/voice/s2s-tool-call-runtime.ts`: call-id dedupe, stale-turn rejection, sanitized outputs, graceful end requests, latency milestones, and result batching. Auto-end timestamps, settle/idle polling, and bounded farewell completion belong in `services/voice/s2s-auto-end-runtime.ts`. Keep `use-s2s-session.ts` focused on duplex transport, mic/playback, session lifecycle, and composing those runtimes.
- Live Voice prompt-dispatch work follows `plans/voice-orchestrator-world-class/PLAN.md` and `CHECKPOINTS.md`. Implement one vertical TDD behavior at a time, keep the scope at faithful target resolution/prompt delivery/transport feedback, and require command evidence plus desktop QA before marking the focused dispatch slice verified.
- Classic push-to-talk STT orchestration for the NL command bar belongs in `services/voice/use-canvas-turn-voice-controller.ts`: mic start/stop/cancel, auto-stop timer, global voice hotkeys, transcript guards (quality, language, replacements) before handing the transcript to the Canvas Voice Adapter, and actionable mic errors.
- Where a typed or spoken utterance goes belongs in the Canvas Voice Adapter, `services/voice/canvas-voice-adapter.ts` (`deliver` / `targets` / `liveTools`, ADR-0053): Voice Intent Router on the Canvas Voice Context, then the command/dictate/terminal/transform/insert route, with a `sent` / `held` / `failed` result. The routes themselves (dictation receipt, prompt insert, terminal submit, note transform, polish, STT decoder context) live in `services/voice/use-canvas-voice-routes.ts`.
