# Terminal V2 DOX

> **2026-11-19: the legacy grid is gone.** Code mode (`workspace-shell`) renders panes itself, so
> the grid path had no caller in the app. Deleted: `LegacyTerminalGrid`, `LegacyTerminalCell`,
> `GridCellRenderer`, `LegacyGridTerminalCellRenderer`, `useCellHandlers`, the legacy pane-layout
> engine and resize/reorder hooks, `layout/TerminalV2{GridRouteSelector,DynamicGridBridge,
> GridTerminalCellSelector,LayoutGridAdapter,LayoutSurface,PaneRenderer,PaneChrome,TerminalPane,
> TerminalHeader,TerminalBody,StatusIndicator}`, `terminal-v2-layout-{policy,keybindings}`, the
> `compat/` audits, manual-QA checklist and deletion map, `quality/terminal-v2-source-budget`, and
> the pane-title turn/refresh pipeline. Sections below that name these files are history. Still
> live: `LegacyInteractiveTerminal` and `useLegacyTerminalRuntime` (Canvas terminal nodes), the
> runtime provider, `InteractiveTerminalV2`, and the session/registry adapters.

## Purpose

- Owns the scratch-built, Terax-inspired terminal runtime replacement for CodeSpace.
- Provides runtime-core services, metadata contracts, renderer-pool abstractions, and compatibility adapters before legacy terminal deletion.

## Ownership

- `contracts/` owns stable TypeScript runtime, metadata, rendering, input, output, and compatibility contracts.
- `compat/` owns one-way adapters that present Terminal V2 through legacy CodeSpace terminal contracts during migration, the compatibility parity audit gate for mixed legacy/V2 rollout, and the stricter legacy deletion-readiness gate for ownership cutover. Compatibility parity and legacy deletion readiness are separate contracts.
- `session/` owns pane/session metadata restore boundaries and repository adapters.
- `runtime/` owns the app-level Terminal V2 runtime container/provider, in-memory session lifecycle services, pane lifecycle adapter seams, native-runtime orchestration/wiring helpers, and pure workspace renderer controllers. It must stay above the CodeSpace route surface so runtime state can survive route navigation.
- `hooks/` owns V2 UI hook boundaries. `useTerminalV2LegacyBridgeFallbackRuntime` is the explicit emergency bridge fallback to the legacy wrapper during migration. `useTerminalV2PaneRuntime` owns V2 pane-runtime seam composition and must absorb future renderer/output/input/geometry replacements instead of expanding legacy `useLegacyTerminalRuntime`. `useTerminalV2NativeRuntime` is the native orchestration shell with the same public terminal handle shape; keep it opt-in until feature-flagged QA proves parity. `useTerminalV2NativeRendererLifecycle` owns renderer creation/disposal, ResizeObserver lifetime, and lifecycle cleanup so the public native hook stays thin. It must not create owned native xterm renderers or start/reattach sessions while a pane is inactive; inactive panes wait for the active path before creating renderer/session work. `terminal-v2-native-runtime-wiring.ts` owns non-React native renderer wiring: renderer handles, search readiness, write scheduler, output/input handlers, activity tracking, resize debouncer/binding, renderer event subscription, and session start orchestration. `useTerminalV2XtermRenderer` owns the local V2 xterm renderer factory seam used during the owned-renderer cutover. `useTerminalV2XtermEvents` owns the local V2 xterm event-subscription seam for input, render, parsed-write, and custom-key handlers. `useTerminalV2Session` owns the app-level V2 session hook boundary for session starter access, session detach access, and direct session-output-to-renderer subscription. `useTerminalV2WorkspaceRendererVisibility` owns CodeSpace-level active-workspace renderer visibility transactions, applying the pure workspace renderer controller so active workspace changes release/bind renderer panes once and route-hidden CodeSpace releases all renderer panes. `useTerminalV2RendererBinding` owns renderer visibility signals, unmount release, and legacy-created xterm slot registration as the fallback renderer seam. `useTerminalV2Geometry` owns the V2 geometry/resize routing seam and no-op/invalid geometry guards before resize reaches the session manager. `useTerminalV2Input` owns the V2 input write routing seam from parsed terminal input to `TerminalV2Runtime.writePaneInput()`. V2 input adapters and pooled-renderer input must normalize an exact single `\r\n` input event to `\r` so WebView/xterm `Shift+Enter` cannot submit duplicate blank commands. `useTerminalV2FocusSearch` owns focus forwarding and search API capture/forwarding so imperative handles and search readiness can move out of the legacy runtime wrapper. `useTerminalV2Suggestions` owns suggestion callback forwarding/remainder state; `useTerminalV2InlineSuggestionOverlay` owns visible inline suggestion anchoring against the currently leased renderer helper textarea before falling back to native/legacy helpers; `useTerminalV2Links` owns terminal link context-menu coordinate normalization/forwarding; `useTerminalV2PooledRendererEvents` owns pooled renderer link/context-menu and custom-key event bridging back into `InteractiveTerminalV2`. `useTerminalV2PooledRendererUiAdapter` owns pooled renderer UI adapter mounting and must lazy-load concrete xterm constructors only after policy enables pooled rendering. Diagnostics hooks under this folder must stay development-only and opt-in.
- `components/` owns V2 terminal UI surfaces such as `InteractiveTerminalV2`, development-only diagnostic panels, native-runtime opt-in policy, and opt-in UI adapters that mount renderer seams without concrete production xterm wiring.
- `geometry/` owns pure Terminal V2 geometry and resize-event semantics: active/live-resize fit decisions, initial geometry start/defer decisions, commit-fit decisions, and PTY resize debounce helpers.
- `input/` owns pure Terminal V2 input-event semantics: inline-buffer reduction, submitted-prompt metadata, and suggestion remainder calculation. CWD markers come from native shell integration, never a synthetic PTY command.
- `output/` owns Terminal V2 output buffering, write-scheduler/backpressure adapters, and PTY output-event semantics used by hidden/detached renderer flows: session-end detection, cwd/OSC parsing, output routing, trust-folder decisions, and suggestion layout signals.
- `rendering/` owns pure renderer-pool policy, lease planning, plan-to-host adapters, xterm-like host adapters, constructor-injected pooled xterm renderer factories, the owned local xterm renderer factory, the owned local xterm event adapter, pooled renderer rollout audit gates, the renderer coordinator, renderer rehydration stores, disabled-by-default pooled DOM slot prototypes, pooled slot factories, and non-production pooled DOM runtime harnesses before any concrete production UI wiring.
- `layout/` owns the scratch-built dynamic Terminal V2 pane layout model, pure tree transforms, the pane-tree controller for active-pane split/close/spatial focus commands, V2 pane chrome controls, the V2 pane renderer adapter over legacy `GridCellRenderer`, the optional direct terminal-only pane seam over `InteractiveTerminalV2`, workspace layout mutation/action helpers, and Terax/Ghostty-inspired layout adapters.
- `quality/` owns Terminal V2-specific maintainability gates such as source file budget analysis.
- Future geometry UI wiring must stay isolated from legacy CodeSpace UI except through explicit adapters.

Pooled xterm slots must detect terminal links with the shared terminal link parser and bubble pooled link context-menu events to `InteractiveTerminalV2`, which owns the visible Open/Copy menu for the active pane. `mountTerminalV2PooledRendererUiAdapter` and `useTerminalV2PooledRendererUiAdapter` are UI seams that install a pooled slot factory into `TerminalV2Runtime` without putting concrete xterm construction directly inside `InteractiveTerminalV2`. `TerminalV2Runtime` may accept or install an enabled pooled DOM slot factory so host-created renderer slots can be exercised without legacy registered slots. `getCurrentTerminalV2PooledRendererRolloutReport()` has pass evidence for the non-production opt-in gate, `plans/codespace-v2/terminal-v2-pooled-dom-default-rollout-tauri-qa-checklist-2026-06-13.md` records post-rollout non-production QA pass, and `plans/codespace-v2/terminal-v2-pooled-dom-production-rollout-plan-2026-06-13.md` owns production rollout. This still does not justify legacy deletion in the same step. `resolveTerminalV2RevealPolicy` owns the pure reveal state decision for hidden/warming/settled transitions during workspace hide/show and first visible paint. `TerminalV2RendererDiagnostics` may render snapshots only outside production and only when explicitly enabled by `lotus:terminal-v2-renderer-diagnostics=1` in localStorage.
- Two renderers can serve one pane during pooled-renderer migration, so ownership must be explicit and single. While `TerminalV2RendererCoordinator.isPaneServedByHostCreatedSlot()` is true for a pane — surfaced to pane owners as `TerminalV2Runtime.isPaneRendererServedByPooledSlot()` — the pane's own xterm is a cold standby: it must not parse live PTY output and must not fit or push PTY geometry. Its output is parked through the `rendererStandbyBacklog` seam into the *standby* ring owned by `TerminalV2PaneBacklogs`, which must stay separate from the *missed* ring used when a pane has no renderer at all — draining the wrong one duplicates scrollback the visible renderer already showed. A fallback bind to that registered slot must replay the standby ring even though the slot declares `liveOutputMode: "external"`, or the fallback renders nothing, and the standby ring must be cleared when that renderer is disposed because the next one starts empty. Activity notification, cwd/OSC parsing, and exit detection still run while parked. Standby is the reason pooled rendering does not double the per-byte cost of every pane.
- Reusing an already leased renderer for focus/activity priority changes must not reattach, refit, drain, or repaint it; the slot ResizeObserver owns real geometry changes and its live-resize transition owns the final commit fit. First bind and release/rebind still restore snapshots and drain output. When a pooled lease is acquired before React registers its pane DOM container, registration must flush pending output and rebind the unattached lease through the snapshot path; an already attached lease must remain untouched.
- Live output into pooled slots is coalesced to one renderer write per frame by `TerminalV2RendererWritePump`; the lease is resolved at flush time, and callers must flush the pump before any lease change (visibility update, fallback) so a batch cannot land in a slot that has moved to another pane. Output for a pane with no lease still goes straight to the rehydration ring.
- Pooled renderer keystrokes must reach the same input pipeline as the pane's own renderer. Panes publish `inputHandler.handleInput` through the `paneInputPipeline` seam (`TerminalV2Runtime.registerPaneInputHandler()`), and `writePooledRendererInput()` routes through it so inline suggestions, submitted-command metadata, activity tracking, and cwd probes behave identically on both renderer paths; the raw session write remains only as the pre-registration fallback.
- `InteractiveTerminalV2` owns shell editing keys for every renderer path: it composes `handleTerminalCustomKeyEvent` so `Cmd+Backspace`/`Cmd+Delete`/`Cmd+Arrow`/`Option+Arrow` reach the PTY (xterm does not encode them on macOS), with the pane owner's handler — dynamic-layout shortcuts — consulted first and authoritative. That handler runs inside xterm's keydown path, so it must never throw: failures are reported and the key is handed back to xterm. Shift+Enter inserts a newline instead of submitting, with the bytes chosen per pane by `resolveTerminalShiftEnterSequence()`: Claude-family agent commands (`claude`/`ccs`/`csp`) take the kitty CSI-u encoding raw, everything else — other agent TUIs and plain shells — takes Meta+Enter. A pane with no agent command is a shell and must not inherit the agent-runner default of "assume claude".

## Work Guidance

- Build runtime-core-first before React wrappers.
- Keep Terminal V2 source files under the hard 400 LOC budget; treat files above the soft 300 LOC budget as split candidates. Native runtime hook orchestration should delegate initial-command, input, output, resize, search, session-start, and status details to runtime helpers instead of growing the hook.
- Prefer dependency-injected repositories, controller factories, and services so core behavior can be tested without Tauri.
- When wiring legacy facades to V2, preserve ordering-sensitive bus behavior: buses may attach before the app-level provider effect installs the V2 adapter.
- Create-time routing policy must keep Canvas terminal sessions on legacy until explicit V2 adapters exist. Historical SSH routing is not a Terminal V2 fallback requirement; the default `PtySessionController` and Bridge headless session path must use local PTY creation even when historical SSH metadata is present. Terminal UI/runtime code must ignore SSH metadata unless a future active product surface reintroduces a dedicated adapter and native command surface.
- Do not add more behavior to legacy `useLegacyTerminalRuntime` for V2 work except typed compatibility seams; add new UI/runtime behavior behind `useTerminalV2NativeRuntime`, explicit bridge-fallback seams, and pure runtime/geometry/input/output/rendering policies such as `TerminalV2SessionStarter`, `createTerminalV2PaneRuntimeAdapter`, `resolveTerminalV2ResizeEvent`, `processTerminalV2InputEvent`, `processTerminalV2OutputEvent`, `createTerminalV2WriteScheduler`, `TerminalV2OutputRing`, `TerminalV2RendererPool`, `TerminalV2RendererAdapter`, `TerminalV2RendererCoordinator`, `TerminalV2XtermRendererHost`, `createTerminalV2LegacyXtermSlot`, `createTerminalV2OwnedXtermRenderer`, `attachTerminalV2XtermEvents`, and pooled DOM factory seams.
- Use `terminalRuntimeV2` from `src/lib/feature-flags.ts` for rollout; the default is ON.
- Do not call Tauri `invoke()` directly from V2 components or services; go through existing `src/lib/tauri-api.ts` or a typed adapter.
- Future layout refactor work should align with Terminal V2 renderer pooling and performance goals: keep layout policy pure/testable first under `layout/`, then wire UI adapters after behavior is proven. The current dynamic layout slice is automatic in development; run `localStorage.setItem("lotus:terminal-v2-dynamic-layout", "0")` and reload to return to the legacy grid.
- Development renderer diagnostics are opt-in: run `localStorage.setItem("lotus:terminal-v2-renderer-diagnostics", "1")` and reload in a non-production build to inspect leases, slots, and waiting panes.
